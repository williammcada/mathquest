# MathQuest v0.14.1 — "Next variant" in the teacher math preview (change specification)

**Status:** Requested by William McAda on 2026-10-16 (Asia/Shanghai): "When I preview content in Math Quest/Math Arcade delivered via Math Engine - I want a 'next variant' button so I can screen the questions quickly. Right now, Math Quest is delivering me the same example question over and over again." Verified release, deployed 16 Oct 2026 — see [release notes](../releases/v0.14.1.md).
**Baseline:** `main` `5a5d7c6` (MathQuest 0.14.0).
**Math Engine:** unchanged (the vendored build MathQuest already records). No Engine change is needed.
**Handbook:** `9d9c80f` (v0.1.12). U-01 (version bump), U-06 (variant 0 is today's sample; nothing else changes), U-07, U-14 (the Engine owns seeded generation; MathQuest only chooses which index to ask for).

## Problem

The setup page's **Preview** button calls `POST /api/engine-preview`, which always generated with seed `preview:<id>` and index 0. The Engine is deterministic, so every preview of a skill showed the identical question. A teacher could not screen what a skill actually produces.

## Change

1. **Worker:** `/api/engine-preview` accepts an optional `variant` (non-negative integer, default 0). `enginePreview(ids, variant)` asks the Engine for the same seed at `index = variant` (clamped to 0…9999). Each returned item carries `variant`. Still teacher-only (v0.14.0 passcode).
2. **Setup page:** the preview panel shows "Variant N" next to the title and a **Next variant** button beside **Close preview**. Next variant regenerates every question in the open preview at the next index. A slow earlier response cannot overwrite a newer one.
3. **Unchanged:** variant 0 is exactly the previous sample. No classroom question, room, record or student data is touched. Preview still says "Preview only. Nothing is saved".
4. **Version:** frontend 0.14.1, Worker 0.14.1 — they deploy together (S-04).
