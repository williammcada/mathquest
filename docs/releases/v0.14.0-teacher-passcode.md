# MathQuest v0.14.0 — teacher passcode (implementation checkpoint)

**Status:** Implementation checkpoint on `implement/v0.14.0-teacher-passcode` (stacked on v0.13.0, PR #15). Not merged or deployed. Spec: [v0.14.0](../change-specs/v0.14.0-teacher-passcode.md).
**Worker change: yes.** Frontend and Worker are both 0.14.0 and must go live together; the frontend refuses a Worker of another version.

## Changes

- Worker: `TEACHER_PASSCODE` secret (8+ characters). `POST /api/sessions` and `/api/engine-preview` need header `x-mathquest-teacher`; `POST /api/teacher-check` verifies it. Wrong → 403; secret missing → 503 "not set up". Constant-time comparison. Existing rooms, joins, teacher links and gameplay unchanged. Rooms created by 0.12.0/0.13.0 stay supported.
- Setup page (site root): passcode screen first; Developer tools and room creation only after it is accepted; remembered on that computer; "Forget teacher passcode on this computer".
- Every practice / DEV / review page (24 files, including historical `reviews/*`, `aerial-practice-v0.x/`, `Ironbreak-v0.1.0-*`): full-screen passcode cover until the server accepts the passcode. **U-01 note:** these historical files received only this access wrapper; their game content and version labels are unchanged.
- `Deploy_Backend_Windows.bat` text updated for 0.14.0.

## Limits

The cover on static practice files is a deterrent: someone who downloads and edits the files could remove it. Student links to a live room still work while the room is open.

## Go-live steps (owner)

1. Cloudflare dashboard → Workers & Pages → `mathquest-prototype` → Settings → Variables and Secrets → Add → Type **Secret**, name `TEACHER_PASSCODE`, value: your passcode (8+ characters) → Deploy/Save.
2. After school: merge PR #15, then this PR; download the repository ZIP from `main`, unzip, run `Deploy_Backend_Windows.bat`.
3. Open the MathQuest site, enter the passcode, create a test room; open a practice page and enter the passcode.
